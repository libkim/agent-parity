판단 실패 기록(2026-09-04): 공유 MCP 기능에서 Codex TOML에 [mcp_servers.name]을 append하는 코드를 새로 작성했는데, 이것이 메모리 1785833807615144982에 이미 기록돼 있던 미해결 버그와 정확히 같은 계열이었다. 그 메모리에는 원인("인라인 테이블이면 invalid TOML이 되는데 mergeTOML은 출력을 재검증하지 않고 성공을 반환")과 수정 방향("append 후 결과를 재파싱해 invalid면 파일을 안 건드리고 경고")까지 적혀 있었다. 세션 시작 memory_recent 응답에 그 항목이 실제로 포함돼 있었는데도 구현 전에 대조하지 않아 같은 결함을 새 코드에 복제했다. 이는 이미 next-patch 후보로 기록된 "에이전트가 메모리를 저장하지만 이후 판단과 작업에서 실제 검색·사용하지 않는 문제"(1785058179344824100)의 구체적 실측 사례다. 일반화: 기존 코드의 어떤 패턴을 새 위치에 복제할 때는 그 패턴에 대한 기존 기록을 먼저 memory_search로 확인해야 하며, 특히 사용자 파일을 편집하는 코드가 그렇다. 하네스 강제 후보로 축적한다(개인 반성이 아니라 구조적 취약점으로 다루라는 사용자 지시 1784562732366387500 계열).
