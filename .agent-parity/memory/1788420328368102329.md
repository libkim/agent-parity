v0.9.6 메모리 생명주기 계약 정리(구현 완료). 공통 패턴은 "요청이 성공한 것처럼 응답하는데 실제로는 다른 일을 하거나 아무 일도 안 함"이었고 네 경로를 막았다. (1) 머지 드라이버가 frontmatter를 created/tags/type만으로 조립해 status를 통째로 버렸다 — 부재=active라 한쪽에서 폐기한 governance 규칙이 태그 추가 같은 사소한 머지 한 번에 부활해 다시 세션에 주입됐다. v0.9.2에 status가 들어올 때 store.go write()만 갱신되고 머지 드라이버가 안 따라간 것. (2) memory_update가 "active"를 받아 은퇴를 되돌릴 수 있었다 → 일방향으로 변경. 되살리려면 현재 규칙을 새 governance 메모리로 쓴다(옛 본문은 이미 바뀐 상황 기준으로 쓰였고 왜 물러났는지가 본문에 없음). deprecated↔merged 이동은 허용 — 사유 정정이지 부활이 아님. (3) memory_update가 타입을 안 봐서 context 메모리에도 성공했는데, recent/search는 status를 필터하지 않으므로 완전한 무효과였다 → governance 전용으로 거부. recent/search는 그대로 뒀다(context에 생명주기를 부여하는 건 기획에 없음). (4) memoryType이 모르는 값을 전부 context로 매핑했고 Add가 그걸 그대로 썼다 — "goverance" 오타가 조용히 context로 저장됨 → Add에서만 엄격 검증, parseEntry는 관대 유지(옛 파일·미래 버전 파일 로드 필요). 머지 status 화해 규칙: 한쪽만 base에서 바뀌면 그쪽 채택, 양쪽이 다르게 바뀌면 은퇴가 active를 이기고 deprecated가 merged를 이긴다. base 부재도 같은 경로. Update가 재활성화를 안 만들지만 손으로 고친 파일이나 옛 서버 머신에서 올 수 있어 그 분기는 방어적으로 남겼다.
