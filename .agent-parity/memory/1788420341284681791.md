v0.9.5 윈도우 CRLF 셸 스크립트 문제와 그 구조(구현 완료). git은 머지 드라이버와 pre-push 훅을 모든 OS에서 sh로 실행하고 훅은 .agent-parity/scripts/pre-push.sh를 exec하므로 shebang이 살아남아야 하는데, Git for Windows 기본 core.autocrlf=true가 체크아웃 시 .sh를 CRLF로 바꿔 "sh\r" 인터프리터를 찾게 만든다. agent-parity 리포 자신은 최초 커밋(v0.6.0, 손으로 넣음)의 `*.sh text eol=lf` 덕에 면역이라 윈도우 CI가 이 시나리오를 재현하지 못했고, 정작 설치처는 관리 블록이 merge 드라이버 줄 하나만 써서 무방비였다. 두 축으로 나눠 해결: .gitattributes 관리 블록이 `.agent-parity/**/*.sh text eol=lf`와 `.agent-parity/bin/agent-parity text eol=lf`(확장자 없는 런처라 suffix 규칙이 놓침)를 추가해 CRLF 발생을 예방하고, PowerShell Write-Text의 Match-Newlines를 우리 소유 실행 파일에만 건너뛰어(Test-LfRequired: *.sh, leaf가 agent-parity 또는 pre-push) 이미 CRLF인 파일을 update가 복구하게 했다. Match-Newlines 자체는 AGENTS.md·.gitignore 같은 사용자 파일에 필요하다 — 한 줄 바꿨는데 파일 전체가 변경으로 잡히는 걸 막는 장치. 남은 커버리지 공백: CI가 보호된 자기 리포를 체크아웃하므로 "윈도우에서 CRLF로 체크아웃된 트리" end-to-end 시나리오는 여전히 재현되지 않는다(RELEASING.md 표에 명시). 관련해서 store.go write()가 뼈대만 LF 하드코딩하고 body는 받은 그대로 넣던 것도 정규화했다.
