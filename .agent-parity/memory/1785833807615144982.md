할일(libkim이 집에서 수정 예정): agent-parity config editor 견고성 3형제 — TOML 손상 버그를 2026-08-04 실측 테스트로 확정함. mergeTOML(config.go, Codex config.toml의 memory MCP 등록)이 기존 파일 뒤에 `[mcp_servers.memory]` 테이블 헤더를 그대로 append하는데, 사용자의 mcp_servers가 인라인 테이블(`mcp_servers = { ... }`)로 써져 있으면 결과가 invalid TOML이 됨(TOML은 이미 값으로 정의된 키를 테이블로 확장 못 함, 파서 에러 'key mcp_servers already exists as a value'). 그런데 mergeTOML은 출력을 재검증하지 않고 nil(성공)을 반환해 rc0 'changed'로 보고 → 사용자 config.toml을 조용히 파싱불가로 손상시킴. 대조: 같은 파일의 retargetTOML은 출력을 재검증해서 안전, mergeTOML만 이 재검증이 빠짐. 흔한 `[mcp_servers.xxx]` 테이블 헤더 형식은 안 걸리고 인라인 테이블 사용자만 걸려 지금껏 안 터짐. 이 버그는 독립 3형제 중 하나로 엮여 있음: (1) JSON addToStringArray가 타입 불일치 시 유저 값을 조용히 덮어써 삭제(데이터 손실), (2) 이 TOML 손상, (3) install-time 에러 처리 비일관(어떤 편집 실패는 경고 후 계속, 어떤 건 exit1로 install 전체 중단, 어떤 건 graceful 안내). 셋은 서로 호출관계로 얽히지 않은 독립 코드 경로라 따로 고칠 수 있지만, 고칠 때 동일 정책을 적용해야 결과가 일관됨: 유저 파일은 건드리지 않고 경고 후 설치 계속(삭제·손상·전체 중단 금지). 수정 방향: mergeTOML은 인라인 테이블이면 파서 기반으로 memory 키를 삽입하거나, 최소한 append 후 결과를 재파싱해 invalid면 파일을 안 건드리고 경고.
