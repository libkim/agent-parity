공유 MCP 매니페스트 기능(.agent-parity/mcp-servers.json → 4개 에이전트 설정 팬아웃) 1차 구현 후 서브에이전트 2개로 검토한 결과, 릴리스 불가 수준의 결함 다수 발견. 커밋 ee2b5ca/dec0779 상태이며 아직 미해결. P0: (1) 사용자 Codex 설정이 인라인 테이블(mcp_servers = { ... })이면 [mcp_servers.name] 테이블을 append하는 순간 invalid TOML이 되는데 exit 0으로 성공 보고 → 이후 메모리 등록·동기화·uninstall 전부 실패, 자가복구 불가. (2) 서버 이름을 TOML 헤더에 따옴표 없이 삽입 — 'my.server'는 중첩 테이블로 해석돼 매 실행 중복 추가 후 3회차에 파손, 'has space'는 즉시 파손. server-filesystem·github.copilot 같은 이름이 흔해 실재 위험. (3) 상태 파일이 전역인데 소유권은 설정별이라, 앞 설정에서 이름을 등록하면 뒤 설정의 사용자 수기 항목을 우리 것으로 오인해 덮어씀. 첫 실행에서 conflict로 올바르게 거부해도 다른 3개 등록이 상태를 채우므로 다음 update에서 조용히 삭제 — 이 기능이 막으려던 바로 그 일. (4) 제거 시 managed에서 이름을 안 지워 상태가 영구 누적 → 나중에 사용자가 같은 이름을 직접 추가하면 매 실행 삭제. (5) unmergeSharedServers는 여전히 TOML 전체 unmarshal/marshal 왕복이라 uninstall이 주석·따옴표·순서를 파괴(sync만 스팬 편집으로 고치고 uninstall 경로를 안 고침). P1 이하: 매니페스트 삭제 시 shell이 early return해 고아 발생하고 status의 'run update' 조언이 무효, 상태 파일 분실 시 영구 conflict로 수정·제거 불가, uninstall이 한 설정 실패해도 상태를 무조건 삭제, status가 서버 수가 아니라 줄 수를 셈, README 두 곳이 'Codex 승인 모드까지 채워집니다'라고 하는데 코드는 일부러 안 채우고 테스트는 부재를 단언(정면 모순), bootstrap/*.ps1의 Unmerge-SharedMcp가 정의만 되고 미호출. 테스트 공백: test_shared_mcp.sh의 충돌 검사가 에러 경로 문구까지 함께 grep해서 기능이 통째로 죽어도 통과, Codex는 제거·uninstall·업데이트 테스트가 전무한데 P0 두 개가 거기 있음, 팬아웃 검사가 이름 문자열만 보고 command/args를 안 봄. 판단: 소유권 모델(전역→설정별)과 TOML 쓰기 전략 두 가지가 설계 결함이라 패치가 아니라 재설계 필요.
